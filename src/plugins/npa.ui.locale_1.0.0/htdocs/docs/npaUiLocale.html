npa.ui.locale — UI Internationalization Plugin

Overview

The npa.ui.locale plugin provides server-side i18n support for NPA UI pages. It collects locale files contributed by any plugin, merges them into a per-locale key/value map, and exposes that map to the browser via HTTP. The npaUi client framework loads this map at startup and resolves all @key references in component configurations and <var> HTML tags automatically.

Extension Point: npa.ui.locale.provider

Any plugin can contribute translation strings by declaring one or more npa.ui.locale.provider extensions in its manifest.json:
 1. {
 2.   "point": "npa.ui.locale.provider",
 3.   "id": "my.plugin.locale.en",
 4.   "path": "i18n/myPlugin_en_US.locale",
 5.   "locale": "en-US"
 6. },
 7. {
 8.   "point": "npa.ui.locale.provider",
 9.   "id": "my.plugin.locale.fr",
10.   "path": "i18n/myPlugin_fr_FR.locale",
11.   "locale": "fr-FR"
12. }
The path is relative to the contributing plugin's directory. Multiple plugins can contribute to the same locale — entries are merged, with later contributors overriding earlier ones for duplicate keys.

It is recommended to register the same file for both "en-US" and "en" (and "fr-FR" and "fr") so that both short and long locale tags resolve correctly.

Locale File Format

Locale files are plain text, one key=value pair per line. Lines starting with # are treated as comments and ignored. Keys are typically dot-separated namespaced identifiers.
 1. # My Plugin - English translations
 2. my.plugin.title=My Plugin
 3. my.plugin.action.save=Save
 4. my.plugin.action.cancel=Cancel
 5. my.plugin.msg.saved=Item {0} saved successfully
Placeholders {0}, {1}, etc. are replaced at resolution time when a data array is passed to npaUi.getLocalizedString().

HTTP Endpoints

GET /i18n/localizationMap?locale=<locale>

Returns the full key/value map for the requested locale as a JSON object. If the locale is not found, the default locale (en-US) is returned as fallback. This endpoint is called by npaUi.initialize() at page load time using navigator.language as the locale.

Example response:
{
  "my.plugin.title": "My Plugin",
  "my.plugin.action.save": "Save",
  ...
}

GET /i18n/localize?ref=@key&values=a,b&locale=en-US

Resolves a single localization key server-side. Useful for server-generated strings or emails. values is an optional comma-separated list of positional substitution values.

Client-side Usage

In browser JavaScript, strings are resolved via npaUi.getLocalizedString():
// Simple lookup — key starts with @
let title = npaUi.getLocalizedString('@my.plugin.title');

// With substitutions
let msg = npaUi.getLocalizedString('@my.plugin.msg.saved', ['myItem']);
// → "Item myItem saved successfully"

// Literal string (no @ prefix) — returned as-is
let raw = npaUi.getLocalizedString('Some literal text');
In HTML, <var> tags are automatically replaced with the localized string after npaUi.render() completes:
<var>my.plugin.title</var>
<!-- rendered as: My Plugin -->
In component configuration JSON, any string value starting with @ is treated as a localization reference and resolved automatically by the component:
{
  "label": "@my.plugin.title",
  "type": "Card"
}
