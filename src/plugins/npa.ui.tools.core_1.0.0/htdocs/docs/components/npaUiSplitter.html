Splitter — npaUi Component

Overview

The Splitter divides its container into two resizable panes separated by a draggable handle. Panes can be arranged side-by-side (default) or top/bottom. Any npaUi sub-components placed inside the panes are automatically rendered after layout is applied.

Configuration

FieldTypeDefaultDescription
verticalbooleanfalseWhen true, panes are stacked top/bottom instead of side-by-side
percentagesnumber[2][50, 50]Initial size of each pane as a percentage of the container; must sum to 100

HTML Structure

Place two child <div> elements inside the Splitter host, each with a data-splitter-target attribute set to "first" or "second". Any npaUi components inside them are declared normally:
 1. <div class="npaUi" id="mySplitter" data-config="/myPlugin/json/splitterConfig.json">
 2.   <div data-splitter-target="first">
 3.     <div class="npaUi" data-config="/myPlugin/json/leftPanel.json"></div>
 4.   </div>
 5.   <div data-splitter-target="second">
 6.     <div class="npaUi" data-config="/myPlugin/json/rightPanel.json"></div>
 7.   </div>
 8. </div>

Example Configuration File

{
  "id": "mySplitter",
  "type": "Splitter",
  "version": "1.0.0",
  "configuration": {
    "vertical": false,
    "percentages": [25, 75]
  }
}

Notes

  • The Splitter is typically placed inside a Card by pre-placing it as a child div of the Card's host element — the Card preserves and re-injects it into its working area.
  • Panes use CSS flex values proportional to the percentages; the 5px resizer thickness is automatically excluded, preventing overflow.
  • Each pane cannot be dragged below 1% of the container width/height.
  • Sub-components are rendered with a 100ms delay after the layout is applied to allow the DOM to settle before npaUi.render() scans for nested component tags.
