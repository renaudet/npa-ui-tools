npa.ui.tools.core — npaUi Client Framework

Overview

npa.ui.tools.core is the server-side plugin that hosts the npaUi client-side UI framework. It serves static assets under /uiTools/, registers the component map API (GET /uiToolsApis/getComponentMap), and provides two extension points for contributing custom UI components and specialized editors.

On the browser side, npaUiCore.js defines the global npaUi object — the runtime that discovers, lazy-loads, instantiates and renders all UI components on a page.

Page Bootstrapping Pattern

Every APAF HTML page follows this standard pattern:
 1. <!-- 1. Include the framework -->
 2. <script src="/uiTools/js/npaUiCore.js"></script>
 3. 
 4. <!-- 2. Declare component placeholders -->
 5. <div class="npaUi" id="navbar" data-config="/myPlugin/json/navBarConfig.json"></div>
 6. <div class="npaUi" id="mainCard" data-config="/myPlugin/json/cardConfig.json"></div>
 7. 
 8. <!-- 3. Initialize and render in a script block -->
 9. <script>
10. function initializeUi() {
11.   npaUi.initialize(function() {
12.     npaUi.onComponentLoaded = function() {
13.       // Called once all components are rendered
14.       let card = npaUi.getComponent('mainCard');
15.       card.setStatus('Ready');
16.     };
17.     npaUi.render();
18.   });
19. }
20. </script>
21. <body onload="initializeUi()">

Component Configuration

Each component placeholder uses one of three resolution strategies, checked in order:
  1. Inline JSON config passed programmatically via npaUi.renderSingleComponent()
  2. data-config attribute pointing to a JSON file URI — the most common pattern
  3. data-ref attribute referencing an entry in the global config loaded via npaUi.loadConfigFrom()
A component configuration JSON file must declare at minimum id, type and version, plus a configuration object specific to the component:
{
  "id": "mainCard",
  "type": "Card",
  "version": "1.0.0",
  "configuration": {
    "label": "@my.page.title",
    "icon": "/uiTools/img/silk/application.png"
  }
}
The type field can be a simple name (resolved in the npaUiCore namespace) or a namespaced name "namespace.ComponentType" for components contributed by extension.

npaUi API Reference

npaUi.initialize(then)

Loads the CSS theme, component model JS, fetches the component map from the server, and fetches the localization map for the browser's locale. Must be called before render().

npaUi.render(targetClass='npaUi')

Scans the DOM for all elements with the given CSS class and instantiates/renders each one. Already-loaded components are re-rendered (not re-instantiated). Calls onRenderingCompleted() when all components are ready.

npaUi.renderSingleComponent(tagId, componentConfig, then)

Renders a single component into the DOM element with id tagId, using the provided config object. Uses the cached instance if already loaded.

npaUi.getComponent(componentId)

Returns the live component instance registered under componentId.

npaUi.onComponentLoaded()

Callback override point — called after all components have been rendered. Override this in your page script to run post-render initialization.

npaUi.fireEvent(actionId, event)

Dispatches an event. Built-in action ids:
  • 'select' — notifies all registered selection listeners for event.source via listener.onItemSelected(event.item)
  • 'redirect' — navigates to event.uri; if event.newWindow === true, opens in a new browser tab
  • Any other id — dispatched to the handler registered via registerActionHandler()

npaUi.on(actionId, callback)

Shorthand for registering an action handler. Equivalent to npaUi.registerActionHandler(actionId, { handleEvent: callback }).

npaUi.registerSelectionListener(source, listener)

Registers a component as a selection listener for another component's selections. listener must implement onItemSelected(item). This wiring is also done automatically when configuration.selectionListener: true and configuration.selectionProvider: "<componentId>" are set in the config.

npaUi.getLocalizedString(stringExpr, data)

Resolves a localized string:
  • If stringExpr starts with @ — looks up the key in the localization map, with optional {0}...{n} substitution from data[]
  • If it starts with # — returns a <span id="..."> wrapper (for programmatic binding)
  • Otherwise — returns the string as-is

npaUi.loadConfigFrom(configFileUri, then)

Loads a global component configuration file (JSON) and merges it into npaUi.globalConfig.

npaUi.unLoad(componentId)

Removes a component instance from the cache, allowing it to be re-instantiated on the next render().

Extension Point: npa.ui.tools.core.component

Plugins can contribute custom components to be available under their own namespace:
{
  "point": "npa.ui.tools.core.component",
  "id": "my.plugin.myComponent.contribution",
  "namespace": "myNamespace",
  "name": "MyComponent",
  "version": "1.0.0",
  "dependency": "/my-plugin/js/myComponent.js"
}
The component is then referenced in config JSON as "type": "myNamespace.MyComponent". The dependency JS file is lazy-loaded by the browser on first use.

The JS file must define the class on the target namespace object:
myNamespace.MyComponent = class MyComponent extends NpaUiComponent {
  initialize(then) { ... then(); }
  render(then) { ... then(); }
}
